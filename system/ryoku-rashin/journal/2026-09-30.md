# 2026-09-30

## Installed llama.cpp + Liquid AI LFM2.5 (user-local, no sudo)

Sudo needs a password on this box and the `cachyos-v3` / `cachyos` pacman DBs
fail signature validation (see gotchas), so this went in under `~/.local/`.

- llama.cpp **b11146 (v0.5.0-dev)** prebuilt Linux **Vulkan** binaries
  -> `~/.local/opt/llama.cpp/b11146/`, stable path via
  `~/.local/opt/llama.cpp/current` symlink.
  Source: `ggml-org/llama.cpp` release `b11146`,
  asset `llama-b11146-bin-ubuntu-vulkan-x64.tar.gz` (30 MB).
- Model **LiquidAI/LFM2.5-1.2B-Instruct-Q4_K_M.gguf** (731 MB, exact size
  verified against HF `x-linked-size`) ->
  `~/.local/share/llama.cpp/models/`.
- Wrappers in `~/.local/bin/`: `llama-cli`, `llama-server` (thin exec shims),
  and `lfm` (model-aware launcher: `lfm`, `lfm --server`,
  env `LFM_MODEL/LFM_NGL/LFM_CTX/LFM_DEVICE/LFM_PORT`).

Verified end to end: `llama-cli` chat, and `llama-server` answering
`/v1/chat/completions` on 127.0.0.1:8080 with an exact-match reply.

### Device selection matters on this machine

Vulkan enumerates the Intel iGPU as **Vulkan0** and the RTX 5070 Ti as
**Vulkan1**. Without `--device Vulkan1` you silently run on the Intel iGPU.
The `lfm` wrapper defaults to Vulkan1.

### Performance: offload is real, but Vulkan is underperforming

`load_tensors: offloaded 17/17 layers to GPU`, model buffer 694.76 MiB on
Vulkan1, KV cache on Vulkan1 — fully GPU-resident.

| path | prompt | generation |
|---|---|---|
| CPU (`-ngl 0`) | 20 t/s | 6.2 t/s |
| Vulkan1, `llama-cli` | ~380 t/s | **~38 t/s** |
| Vulkan1, `llama-server` | ~300 t/s | ~35 t/s |
| Vulkan1, `llama-bench` | 3789 t/s | **~173 t/s** |

The 4.5x gap between `llama-bench` and the real chat/server paths is unresolved.
`nvidia-smi` during sustained generation shows only 10-19% GPU utilisation,
735-1170 MHz SM clocks and ~25 W — the GPU is idle-stalling, not
compute-bound. Not flash-attention (`-fa on` made no difference), not context
depth (bench holds 156 t/s at d8192), not cold shader cache (server stays at
~35 t/s over repeated warm requests).

Untried: the **CUDA** backend, which is the right one for this NVIDIA GPU.
Two routes, both heavier than what was done here —
`sudo pacman -S llama-cpp ggml-cuda` (Arch ships `llama-cpp 0.5.0` +
`ggml-{cuda,vulkan,hip,sycl,...}`; `ggml-cuda` pulls `cuda` + `nccl`, multi-GB),
or the upstream prebuilt `llama-b11146-bin-ubuntu-cuda-13.4-x64.tar.gz`
(149 MB) plus `cudart-llama-b11146-bin-ubuntu-cuda-13.4-x64.tar.gz` (440 MB).

For a 1.2B model ~35-38 t/s is perfectly usable, so this was left as-is.

## Solstice shaderpack: first visual fixes

User confirmed the pack loads, then reported PNG-like items and a dark world.
Fixed missing item alpha rejection, double-normalized lightmaps, unconditional
black shadow tint, shadow sampler mode, incorrect preprocessor enums, missing
moon transmittance, held-item projection and backwards dark adaptation.

Added a native OpenGL offscreen regression tool: all 38 shader pairs compile/link
on the NVIDIA GPU, and six rendered-pixel checks pass. The pre-fix backup fails
all six. Static lint also passes. Updated source and rebuilt the sibling ZIP;
an in-game reload is still needed to confirm the scene's appearance.
See `memory/solstice.md` and the source pack's `NOTES.md` for paths and details.
